Single Instance and Unique Extraction Paths

The 'SingleInstance' parameter controls what happens on a repeated start when an SFX archive copy is already running and extracting into the same folder ('InstallPath'):

- 'SingleInstance' = "0" - the check is off (default, previous behaviour)
- 'SingleInstance' = "1" - the second copy exits at once without extracting or deleting anything
- 'SingleInstance' = "2" - the second copy activates the window of the first copy and exits

The check is performed only when 'InstallPath' is specified. Without an explicit path the module creates a separate temporary folder for each run, so the check is not needed. The guard works within the user session.

As a result the second copy cannot delete the files of the running first copy: it exits before extraction.

Parameters that support variable substitution also accept '%SfxVarPID%' (or '%%PID%%') - the current process identifier. This allows each copy to extract into its own folder:

InstallPath="%TEMP%\\MyApp_%SfxVarPID%"

The extraction folder is deleted with a limited number of attempts (about one second at most). If a file is held by another application, the free files are deleted while the locked file and the folder remain; there is no one-minute wait.

Adjourn The SFX Archive Can:

- By Clicking "No" Or "Cancel" In The Dialoges Where They Are Provided
- By Clicking "Close" (Which In The Upper Right Corner Of The Window) With The Exception Of Extraction Dialog If The Button is Blocked By The Parameter 'GUIMode' Or Key '-gmX' Equal To 1
- By Clicking 'ExtractCancelText' In The Extraction Dialog If It Is Not Hidden Parameter 'GUIMode' Or Key '-gmX' Equal To 1
- Pressing [Esc] Key On Your Keyboard (If The Parameter 'GUIMode' Or Key '-gmX' Equal To 1, Then The Extraction Dialog Does Not Work)

========================================================================
Loader Mode
========================================================================

Loader Mode (External Archive)

In loader mode the module does not contain the payload. The 7z archive is stored next to the loader and is passed as an argument, so the same module can be reused with different archives.

Supported forms:

- loader.exe payload.7z - the archive is passed on the command line
- drag & drop of the archive onto loader.exe
- Archive="payload.7z" in the configuration file (used when no argument is given)

The archive argument is removed from the command line before RunProgram is executed, so the payload program does not receive it.

Building

Concatenate the module and the configuration. The archive itself is not embedded:

copy /b 7zsd_LZMA.sfx + loader.txt + payload.7z loader.exe

Use a module that supports the compression method of the archive: the base 7zsd.sfx handles Copy and LZMA, while LZMA2, Deflate and PPMd need the corresponding module or 7zsd_All.sfx.

Configuration

;!@Install@!UTF-8!
Title="My loader"
Archive="payload.7z"
;!@InstallEnd@!

The first line enables UTF-8 and is required for non-ASCII text; the last line terminates the configuration.

Installation Configuration Inside The Archive

If the module finds no configuration after its own body, it looks inside the archive for *.sfx.config (for example app.sfx.config.txt) and applies it as the installation configuration.

Notes

- The archive is opened by the same 7-Zip core as a regular SFX archive. Encrypted archives ask for a password unless Password or SfxAuthor is set.
- The module exit code 2 means that the archive could not be opened.
